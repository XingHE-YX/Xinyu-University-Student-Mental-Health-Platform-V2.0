## 2. 首轮交付物

首轮只需要：

1. 一套统一视觉基线；
2. 约 18–22 个基础画面；
3. 一条从首次使用走到后台演示的可点击路径。

普通、较高分数、安全支持、空、失败和冲突状态优先作为基础画面的状态变体，不为每个状态制作独立页面。

## 4. 制作批次

### 4.1 批次一：视觉基础与今日

制作 M-01 至 M-05，走通：

首次使用 → 同意说明 → 身份核验 → 今日未记录 → 记录心情 → 今日已记录。

本批次只检查留白、字体、背景、按钮、弹层、底部导航和返回方式。

### 4.2 批次二：自测与结果

制作 M-06 至 M-11，走通：

自测中心 → 模块开始 → 答题 → 安全确认 → 支持资源 → 完成记录 → 结果 → 历史。

GAD-7 和睡眠使用同一答题骨架的内容变体，不重新制作三套布局。

### 4.3 批次三：树洞与我的

制作 M-12 至 M-16，走通：

树洞 → 首次发帖同意 → 写下此刻 → 内容检查 → 正常公开或保护展示 → 详情 → 我的内容 → 删除或撤回。

本批次重点检查匿名身份、公开边界和支持资源返回来源。

### 4.4 批次四：后台 Web

制作 W-01 至 W-05，走通：

固定账号进入 → 工作台 → 认领任务 → 统一详情 → 提交或冲突 → 审计。

本批次使用合成任务，不制作批量审核、高级搜索、复杂审批链或移动端后台。

不使用真实姓名、学号、电话号码、学校部门、真实支持联系人或真实安全支持任务。

## 6. 可点击交互范围

首轮只制作页面跳转、返回、弹层、选项选择、筛选、答题前进/返回、结果状态切换、发帖状态切换、删除确认、后台认领、提交和冲突。

不制作真实网络请求、复杂动画、正式 AI 调用、真实身份核验、多级审批、数据导出、高级筛选或 Lieflat Charts Skill 运行依赖。

## 7. 每批交付检查

每批完成后提交：

- 默认状态画面；
- 关键状态变体；
- 一条可点击路径；
- 一份当前批次的状态检查表；
- 一组目标尺寸截图。

批次之间不同时修改视觉、文案和交互。上一批确认后再进入下一批。

## 8. 尺寸检查

学生端检查 360px、375px、393px 和系统字体放大；Web 检查 1280px、1440×900。每次检查长文案、题目选项、输入框、定位尺、回答指纹、支持资源、底部导航和 Web 操作区。

主要操作热区不小于 44px，任何画面不得出现横向溢出、按钮遮挡或返回死路。

## 9. 首轮结束判断

M-01 至 M-16 和 W-01 至 W-05 的产品设计与静态高保真评审已经收口。开发完成后仍需让核心路径可点击走通，并通过六条跨页面回归与目标尺寸检查。本文不制定技术实现规划，等待用户提供开发流程。
