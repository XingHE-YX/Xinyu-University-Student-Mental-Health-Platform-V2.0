本文用于把已经确认的学生端、树洞、我的、结果页和后台方案收成一套可连续体验、可评审、可答辩的高保真基线，不新增产品功能。技术架构另由 V2 技术规范冻结。

## 2. 原型目标

首轮原型需要验证四件事：

1. 用户能否从首次使用自然走到今日，并完成一次私密记录；
2. 自测、结果、历史和支持资源能否形成安静连续的阅读路径；
3. 树洞、我的和数据管理能否保持匿名与私密边界；
4. 后台 Web 能否在不泄露不必要信息的前提下完成受限演示流程。

原型优先验证页面气质、信息层级、关键路径和全状态理解，不追求复杂动效、完整后台配置或真实服务接入。

## 3. 页面模板

全项目只保留三种基础模板：

| 模板 | 使用页面 | 结构 |
| --- | --- | --- |
| 移动端阅读式 | 今日、结果、历史、树洞、我的、支持资源 | 连续阅读、细线分隔、少卡片 |
| 移动端答题式 | PHQ-9、GAD-7、睡眠 | 一题一页、低压力、无游戏化 |
| Web 工作台式 | 固定账号、任务队列、统一任务详情、异常状态、审计 | 左侧导航、列表与详情、权限明确 |

后台工作台完全独立为 Web 原型，不放入微信小程序底部导航和移动端页面。

## 4. 四批制作顺序

### 4.1 第一批：首次使用与今日闭环

覆盖：

- 首次使用与基础同意；
- 说明展开；
- 身份核验中；
- 身份核验失败；
- 今日未记录；
- 每日心情记录弹层；
- 今日已记录。

主路径：

首次使用 → 同意 → 身份核验 → 今日 → 记录此刻 → 今日已记录。

第一批只验证背景、字体、留白、底部导航、按钮、列表行、弹层和返回方式。

### 4.2 第二批：自测与结果闭环

覆盖：

- 自测中心；
- 模块开始说明；
- 一题一页答题；
- 退出确认；
- PHQ-9 安全确认；
- 支持资源优先页；
- 普通结果；
- 较高分数结果；
- 安全支持结果；
- 历史记录；
- 睡眠观察结果。

第二批重点验证分数定位尺、回答指纹、历史轨迹、睡眠三条观察线和 AI 失败回退。

### 4.3 第三批：树洞与我的

覆盖：

- 树洞公共页及空状态；
- 社区说明；
- 发帖页；
- 发布检查中；
- 正常公开；
- 保护展示；
- 等待确认；
- 帖子详情；
- 我的；
- 支持资源；
- 数据与隐私；
- 删除确认。

不同审核状态使用同一页面骨架，通过状态变体表达，不为每种状态新增页面。

### 4.4 第四批：后台 Web 与演示闭环

覆盖：

- Web 登录；
- 固定账号进入；
- 工作台队列；
- 统一任务详情；
- 认领成功；
- 认领冲突；
- 无权限；
- 审计日志；
- 演示模式；
- AI 失败后的固定规则结果。

该批只制作受限模拟工作流，不承诺真实学校危机处置能力。

## 5. 状态制作原则

首轮预计制作约 18–22 个基础画面，再通过状态变体覆盖完整流程。状态优先采用同一画面切换：

| 场景 | 处理方式 |
| --- | --- |
| 今日未记录/已记录 | 同一页面状态切换 |
| 树洞正常/保护/待确认 | 同一内容行或详情状态切换 |
| 普通/较高分数结果 | 同一结果页改变支持资源位置 |
| 安全支持结果 | 独立保护展示状态 |
| 后台认领冲突 | 统一详情页切换为只读 |

只有当信息可见范围或用户下一步发生根本变化时，才进入独立页面。

## 6. 视觉评审基线

学生端继续使用暖雾纸白纯色背景、深灰绿正文、静谧青操作色和砖红安全资源小范围强调。页面统一使用 20px/24px 左右留白、8/12/16/24/32px 间距、22px 标题、16px 正文、14px 辅助文字、48px 主按钮和不小于 44px 的主要热区。

首轮不加入渐变、纹理、噪点、发光、阴影堆叠、卡片墙、大面积状态色、庆祝动画、健康指数、雷达图或综合风险图表。

图表先使用静态结构和固定合成数据验证可读性，不制作高级动效，不安装 Lieflat Charts Skill，也不引入运行时依赖。

## 7. 评审关卡

### 关卡一：视觉基线

从三种页面模板各选一个代表画面，检查背景、字体、间距、按钮、分隔线和页面密度。

### 关卡二：核心路径

检查首次使用 → 今日 → 自测 → 结果 → 历史的连续性，确认返回后不丢失来源和状态。

### 关卡三：安全与隐私

检查安全支持资源优先、分数延后展示、AI 隐藏、树洞不自动公开、个人内容不泄露和删除说明。

### 关卡四：边界状态

检查空状态、加载中、失败、权限不足、退出、删除、撤回和并发冲突。

### 关卡五：跨尺寸与演示

检查移动端 360px、375px、393px、字体放大，以及 Web 端 1280px、1440px。最后按答辩路径完整走一遍。

## 8. 单页评审问题

每个页面统一检查：

- 我现在在哪里？
- 我现在可以做什么？
- 这一步会保存、公开或改变什么？

页面必须让用户清楚当前状态、下一步操作和数据边界，不用颜色单独传达含义。

## 9. 首轮验收条件

- 用户能从首次使用走到今日并完成一次心情记录；
- 三个自测模块都能走通主要路径；
- 普通、较高分数和安全支持状态语义清楚；
- “较高分数结果”不会被理解为后台重点观察对象；
- PHQ-9 安全分支不暴露不必要信息；
- 睡眠结果不显示未经确认的分数或等级；
- 树洞公开、保护展示和非公开状态不会混淆；
- 删除、退出和返回路径清楚；
- 360px、375px、393px 和字体放大时无横向溢出；
- Web 端列表、详情、任务能力和冲突状态可读；
- AI 失败时固定结果仍然可用；
- 页面没有新增诊断、风险等级或真实处置承诺。

## 10. 答辩演示路径

主路径控制在约 5–7 分钟：

首次使用 → 今日记录 → 进入自测 → 完成 PHQ-9 → 查看普通或较高分数结果 → 查看历史 → 进入树洞 → 发布匿名内容 → 查看我的与支持资源 → 切换到后台 Web 演示审核状态。

安全支持和删除流程作为备用路径，不放进主路径，以保持演示连续和易于掌控。

## 11. 首轮暂不制作

- 真实学校资源配置；
- 真实身份核验接入；
- 正式 AI 服务接入；
- 批量审核和高级搜索；
- 数据导出；
- 移动端后台；
- 独立演示中心；
- 高级图表动效；
- Lieflat Charts Skill 安装。
